## 1. 设计原则

1. **老人能懂，子女好用**：老人账号默认大字极简模式（单屏一个主任务、正文 ≥18pt、主流程 ≤3 步）；子女/家属视图信息密度正常。
2. **透明有温度**：家人间默认全透明，界面主动展示"谁做了什么"（"爸爸 08:02 已打卡 · 由女儿代点"），让留痕成为安心感而不是监控感。
3. **闭环看得见**：每个提醒/订单/报销都有明确状态标签，永远回答"现在到哪一步了、下一步谁来做"。
4. **隐私分层可见**：对家人透明、对陪诊师最小化——分享码页面明示授权范围与有效期，撤销入口常驻。
5. **不扮演医生**：所有 AI/预警文案避免"诊断/治疗"字样，统一用"建议就医确认"。

## 3.1 家庭端页面分区改造（评审意见落实，硬性要求）

**评审意见**：整个页面需要分区，按照需求文档功能分区，不要所有功能都杂糅在一个页面。

**现状问题**：当前原型把健康档案、预警、提醒、资料、陪诊全部堆在首页 + 弹窗里，首页滚动过长、功能入口不清晰，也和需求文档的功能分区对不上。

**改造方案**：家庭端改为**底部 5 Tab 分区**，每个 Tab 对应需求文档的一个功能域，Tab 内再按子功能分区块：

| Tab | 承载功能 | 对应需求 | 现有原型元素的归属 |
| --- | --- | --- | --- |
| 首页 | 家庭成员切换 · 今日待办（服药/提醒闭环） · 最新预警卡 · 就诊倒计时 · 快捷入口 | FR-02 预警 / FR-03 提醒 / FR-04 告知 | 首页的 hero 卡、今日服药提醒、健康预警卡保留在此 |
| 健康档案 | 档案详情（慢病/过敏/用药/手术） · 日常记录（血压/血糖/体重，手动+设备） · 健康趋势周报月报 | FR-01 | 目前散在首页信息卡与资料库中的"健康"类内容归此 |
| 医疗资料 | 就诊列表 · 就医信息卡 · 就诊准备清单 · 分享码 · 资料整理/OCR 导入 · **保险报销入口** | FR-05 / FR-06 | 现有"资料库"视图 + 整理资料弹窗 + 分享码归此；保险报销（成员 B 模块）在此分区做双入口卡 |
| 陪诊 | 挑陪诊师（商城入口） · 发布需求 · 我的陪诊单（履约进度+佐证查看） | FR-08 / FR-12 | 现有陪诊视图 + 订单卡保留在此 |
| 我的 | 家庭成员管理 · AI 助手入口 · 设备管理（手表接入入口） · 授权记录 · 设置 | FR-07 / FR-08-4 | 现有"我的家庭"视图 + 授权与访问记录归此 |

分区规则（开发必须遵守）：

1. **一个 Tab 只回答一类问题**：首页"现在怎么样"、档案"长期健康"、资料"就医凭证"、陪诊"服务进行到哪"、我的"家庭与设置"。
2. **首页只放状态和入口，不放完整功能**：任何超过一屏的操作引导到对应 Tab 完成，首页不再新增功能块。
3. **跨域内容用跳转不复制**：如首页预警卡点击跳预警中心，不把预警列表复制到首页。
4. **陪诊师端、商城沿用同样原则**：陪诊师端按"接单大厅 / 订单执行 / 我的"三分区，不新增杂糅页面。

## 5. 页面规格

### 5.1 家庭端

**首页看板**
- 顶部：家庭成员切换器（头像横滑）+ 未读预警角标。
- 三卡片纵向：① 今日待办（服药/量血压，可直接"已完成"闭环，显示代打卡人）② 最新预警（级别色条）③ 下一场就诊倒计时 + "准备清单"入口。
- 底部 Tab（分区改造后）：首页 / 健康档案 / 医疗资料 / 陪诊 / 我的（分区规则见 §3.1）。

**健康档案页**（成员 A）
- 成员维度档案：过敏史置顶红色强提示（对齐基准稿 2 的红字处理）；慢病/用药/手术分区白卡。
- 日常记录：手动录入浮层（指标大按钮网格）+ 设备同步记录带"设备"来源标。
- 趋势：周/月切换，曲线 + 一句话解读灰字。

**提醒中心**
- 今日待办按时间轴排列；每项：标题 + 时间 + 渠道 icon（App/微信/短信/电话）+ 状态 chip。
- 已超时项升级为橙色边框并显示"已升级至短信提醒"。
- 自定义提醒：模板选择（高血压套件/糖尿病套件/自定义）→ 频率/执行人/渠道勾选。

**医疗资料**（成员 A）
- 就诊列表（按人/时间）→ 就诊详情：就医信息卡（基准稿 2 同款布局：行式 label 左 value 右）、准备清单（基准稿 1）、资料附件、分享记录。
- 分享页按基准稿 3：二维码 + 倒计时 + 授权开关 + 访问记录 + 撤销按钮（红字、二次确认弹窗）。
- OCR 导入：拍照 → 识别结果对照页（左原图右字段，字段可改）→ 确认入库。

**保险报销**（成员 B）
- 首页双入口卡：社保医疗保险 / 商业医疗保险，各带待办进度数。
- 保单详情：保障信息 + 关联就诊列表。
- 材料包页：材料清单（✅有/❌缺）、关联渠道、每渠道进度状态机（`待整理→已提交→待补件→处理中→已办结`）。
- 进度详情：状态时间线 + 补件记录 + 处理结果输入。
- 页脚固定免责声明："仅作资料整理与进度记录，不构成理赔依据"。

**陪诊（家庭侧）**
- 挑陪诊师：跳商城模块。
- 发布需求：基准稿 4 的表单（医院/日期/需要的帮助）+ 知情勾选（默认不勾）+ 底部灰字"演示预约，不会真实联系服务人员"。
- 我的陪诊单：订单状态步骤条（接单→服务中→已完成），展开可见陪诊师实时勾选的清单项与佐证缩略图；完成后"下次复诊"自动生成提醒卡。

**AI 助手**
- 对话窗 + 顶部语音大按钮（老人模式默认语音优先）。
- 快捷指令 chips："总结妈妈本周健康""生成就诊准备清单""今天该吃什么药"。

### 5.2 陪诊师端（成员 C）

- **接单大厅**：卡片流（医院/日期/服务项/报酬），无任何医疗隐私字段；顶部"商城挂单"入口。
- **订单详情**：仅显示分享码授权内容（医院、时间、服务需求、诊前自我描述若授权）；醒目提示"您无法查看完整病历"。
- **清单执行页**：8 步默认清单（需求文档 §FR-09）竖向步骤条，每步：动作名 + 说明 + "完成并上传佐证"按钮 → 拍照/选图 → 该步变绿。每步完成后家庭端即时可见（页面顶部小字"已同步至家属"）。
- **服务小结**：全部完成后生成服务单预览 + "下次复诊提醒已推送给家属"确认。
- **我的**：简介/资质上传（带审核状态 chip）、档期日历（批量设可约时间并"上架商城"）、收入记录（模拟金额）。

### 5.3 社区商城（成员 C）

- **商城列表**：陪诊师卡（头像/姓名/年限/服务医院/评分/最近可约日），筛选：医院、日期、服务类型。
- **服务者主页**：简介、资质（已审核标识）、可约时间格、价格（模拟）、"预约"主按钮 → 走基准稿 4 表单。
- **需求区**：需求帖卡（医院/日期/需求描述/预算可选/发布时间）；陪诊师点"联系并接单"→ 需求帖转订单；家庭端收到接单通知。
- **合规位**：列表页与主页固定声明"陪诊师不提供诊断或治疗建议"。

### 5.4 平台后台

- 审核队列（陪诊师资质/佐证抽检）、紧急介入工作台（紧急预警列表 + 一键外呼/联系家属按钮 + 处理记录）、订单仲裁（双方留痕与佐证对照）、运营看板（模拟数据）。
- 视觉沿用同套 tokens，中性化处理（白底、弱化绿色）。

## 6. 关键交互流程

**① 预约陪诊（家庭 → 履约 → 回传）**
```
商城挑人/发需求帖 → 填写基准稿4表单 → 勾选知情授权 → 提交
→ 陪诊师接单(家庭端状态变为"已接单") → 逐步执行清单(家庭端实时亮绿)
→ 服务单回传 + 下次复诊自动转提醒 → 家庭端留档
```

**② 分享码**
```
就医信息卡页点"生成就诊分享码" → 选范围 → 二维码+10min倒计时
→ 陪诊师/医生扫码（仅见范围内字段）→ 访问记录落家庭档案
→ 随时撤销 / 到期自动失效
```

**③ 提醒闭环**
```
到期提醒 → 老人渠道逐级升级(App→微信/短信→电话)
→ 任一家人可代点"已吃药/已查看" → 闭环留痕(执行人+时间) → 提醒结束
超时未闭环 → 提醒中心橙色超时态 + 首页置顶
```

**④ 报销材料包**
```
保单详情 → 关联某次就诊 → 生成/复用材料包(一份)
→ 清单核对(✅/❌) → 各渠道独立推进状态机 → 时间线留痕 → 已办结归档
```

## 8. 文案规范

- 称呼用"爸爸/妈妈/王阿姨"，不用"患者/用户"。
- 预警文案给动作不给判断："收缩压连续 7 天高于 140，建议复诊时告知医生"。
- 免责文案三件套（必须在场）：信息卡"不替代医疗判断"；陪诊"不提供诊断或治疗建议"；保险"不构成理赔依据"。
- 老人模式文案短句化："该吃药了" 而非 "您有一个服药提醒待处理"。
