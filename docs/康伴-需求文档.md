## 1. 产品概述

### 1.1 一句话定位

让一线城市子女通过一个平台"看得到、管得住、放得下心"地照护老家父母：健康档案 → AI 预警 → 分级告知 → 陪诊就医 → 报销归档，全链路闭环。

### 1.2 目标用户

| 角色 | 画像 | 核心诉求 |
| --- | --- | --- |
| 家庭成员（子女） | 一线城市工作，有支付能力 | 远程掌握父母健康、就医、报销情况 |
| 被照护者（老人） | 三四线城市，数字化能力弱 | 少操作、少跑腿、有人管 |
| 陪诊师 | 本地服务人员 | 接单赚收益、任务清晰、不背医疗责任 |
| 平台运营 | 极客松团队 / 后期机构 | 审核、人工介入、留痕合规 |

### 1.3 本期范围（四端一后台）

```
┌──────────────────────────────────────────────────┐
│                     康伴 App                       │
├────────────┬────────────┬───────────┬────────────┤
│  家庭用户端  │  陪诊师端   │  社区商城   │  平台后台   │
│ （主面板）   │ （接单履约） │ （供需撮合） │ （运营介入） │
└────────────┴────────────┴───────────┴────────────┘
```

- **家庭用户端（主面板）**：所有家庭成员共用一个面板，通过角色权限区分能力，全程操作留痕。承载健康档案、预警、提醒、医疗资料、保险报销、AI 助手、陪诊预约。
- **陪诊师端**：接单、按项目清单履约、上传佐证、同步进度；管理个人简介与档期并上架商城。
- **社区商城**：陪诊师发布简介与可约时间（商城）；家庭发布需求、陪诊师自行联系接单（需求区）；家庭也可浏览并直接预约陪诊师。
- **平台后台**：成员/服务者审核、订单仲裁、紧急事件人工介入、内容运营。

## 2. 全局机制

### 2.1 角色与权限模型

| 能力 | 老人（被照护者） | 成年家庭成员 | 家庭管理员 | 陪诊师 | 平台 |
| --- | --- | --- | --- | --- | --- |
| 查看家庭健康档案 | ✅ | ✅ | ✅ | ❌（仅分享码任务信息） | ❌（仅紧急介入时） |
| 编辑健康档案 / 日常记录 | ✅ | ✅ | ✅ | ❌ | ❌ |
| 处理提醒（已吃药/已查看） | ✅ | ✅ | ✅ | ❌ | ❌ |
| 发布/预约陪诊 | ✅（简化） | ✅ | ✅ | — | ❌ |
| 接单、履约、上传佐证 | ❌ | ❌ | ❌ | ✅ | ❌ |
| 成员管理、角色分配、撤销分享 | ❌ | ❌ | ✅ | ❌ | ❌ |
| 审核服务者、紧急订单仲裁 | ❌ | ❌ | ❌ | ❌ | ✅ |

规则：

1. **统一主面板**：家庭端不区分"老人版/子女版"两套界面，同一面板，按角色渲染可用功能；老人账号可开启"大字极简模式"（见 3.1）。
2. **家人无隐私（默认全透明）**：同一家庭内，健康档案、日常记录、服药打卡、陪诊记录、就诊资料、报销进度对全部成年家庭成员默认可见、可互相提醒。该默认不可整体关闭，是产品价值观（"异地子女及时掌握老人状况"）的一部分。
3. **操作留痕**：家庭内所有写操作（改档案、打卡、处理提醒、创建/撤销分享码、改报销进度）写入操作日志，日志对全家可见、不可删除，仅显示"谁·何时·做了什么"。

### 2.2 老人友好提醒（多触点降门槛）

老人账号可按提醒项勾选通知渠道：**App 推送 / 微信通知 / 短信 / 电话语音播报**。

- 电话语音为增值能力：系统外呼并语音播报提醒内容（"该吃降压药了"），老人按键或语音回复"已吃药"即可闭环，无需打开 App。
- 未闭环的提醒按渠道逐级升级：App（静默）→ 微信/短信（+30min 未处理）→ 电话（+2h 未处理，可配置）。

## 3. 功能需求（家庭端）

### FR-01 健康档案及管理

| 编号 | 功能点 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| FR-01-1 | 健康档案 | 慢病、过敏史、长期/当前用药清单、手术史；按家庭成员（人）建档 | 每位成员有独立档案页；过敏史置顶强提示（红色） |
| FR-01-2 | 日常记录 | 血压/血糖/体重/心率/血氧/睡眠；手动录入 + 硬件自动同步（见 FR-09-3） | 记录带来源标记（手动/设备）；录入 ≤3 步完成 |
| FR-01-3 | 健康趋势 | 周报/月报：指标曲线 + 一句话解读（"本周血压平稳"） | 子女不点开明细也能看懂；支持按成员切换 |

### FR-02 健康预警（AI 分析，三级）

| 级别 | 触发条件（首版规则引擎，后期叠加模型） | 通知动作 |
| --- | --- | --- |
| 🟡 提醒级 | 漏吃药、复诊临近（提前 3 天）、指标缓慢漂移（如收缩压连续 7 天 >140） | App / 微信推送 |
| 🟠 关注级 | 心率/血氧超出个人阈值、跌倒检测触发（硬件） | 即时推送 + 短信（全家） |
| 🔴 紧急级 | 一键呼 120、跌倒后无响应（硬件） | 电话 + 短信紧急联系人 + 平台人工介入 |

验收标准：预警必须落到"提醒中心"列表（不丢事件）；每条预警可标记"已处理/误报"，留痕。

**演示版实现映射（当前原型已落地）**：原型以三级色卡呈现——🔴 紧急级（红：电话外呼演示 + 强提醒 + 平台介入记录）、🟠 关注级（黄：App 推送 + 漏服超时触发）、🔵 提醒级（蓝：进入每日健康汇总）；触发源为血压读数规则（≥180/110 红、≥160/100 黄、≥140/90 蓝）与模拟手表跌倒事件。命名与色彩对齐以此为准，页面分区见设计文档 §3.1。

### FR-03 自定义提醒与服药管理

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| FR-03-1 | 自定义提醒项目 | 通用提醒引擎：名称（量血压/打胰岛素/复诊…）+ 时间/频率 + 执行人 + 提醒渠道；提供高血压、糖尿病等常见模板一键创建 |
| FR-03-2 | 提醒闭环 | 提醒必须由相关角色点击「已吃药 / 已查看 / 已完成」方可结束；超时未闭环升级通知（见 2.2）；闭环动作留痕（谁点的） |
| FR-03-3 | 服药打卡视图 | 今日待办列表（按时间排序），全家均可代打卡，打卡显示执行人 |

### FR-04 家人告知（分级通知）

| 级别 | 内容 | 通道 |
| --- | --- | --- |
| 日常 | 健康日报/周报 | 静默推送（App 内可看） |
| 异常 | 预警事件 | App + 微信 + 短信 |
| 紧急 | 紧急预警 | 电话 + SMS 直达紧急联系人 + 平台介入 |

### FR-05 医疗资料

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| FR-05-1 | 就医信息卡 | 汇总过敏史、重要病史、长期/近期用药、紧急联系人、近期就诊；供就诊时主动展示（参考现有演示稿） |
| FR-05-2 | 就诊准备清单 | 按次生成：医保卡/身份证、近期检查报告、当前用药清单、想问医生的问题、诊前自我描述；勾选进度可保存、可由家人协同勾选 |
| FR-05-3 | 分享码 | 就医信息卡/本次任务信息生成二维码（默认 10 分钟有效），扫码方仅见授权范围内容；访问记录写入家庭档案，可随时撤销（对应"分享就医资料"演示页） |
| FR-05-4 | 就诊资料整理 | 拍照上传病历、报告、发票；按"人/时间/医院/类型"自动归类，可手动修正 |
| FR-05-5 | 诊疗记录导入（OCR） | 拍照/上传 → OCR 识别 → 结构化字段（医院/科室/日期/诊断/用药）→ 人工确认后入库；识别结果必须可改，未确认不入档案 |

### FR-06 保险报销（保单优先）

详细方案见《项目设计书》模块八，此处锁定需求口径：

1. 保险首页分「社保医疗保险」「商业医疗保险」两个入口；从参保档案/保单进入，创建或关联一次就诊的**材料包**。
2. **材料包只存一份**（一次就诊一份），每个关联保险渠道各自维护材料清单与办理进度。
3. 进度状态机：`待整理 → 已提交 → 待补件 → 处理中 → 已办结`（补件可回到处理中），记录状态变更时间、补件记录、处理结果。
4. **首版边界（红线）**：只做资料归档、识别后修改、材料清单、进度记录；**不做**保险销售、自动核保/核赔、金额计算、自动提交理赔。
5. 演示版使用本机浏览器存储 + 模拟保单/票据。

### FR-07 AI 管理助手（贯穿层）

- 面向子女：总结父母健康周报、回答健康咨询、生成就医准备清单。
- 面向老人：语音交互（"小伴，今天该吃什么药"），返回当日用药与待办。
- 合规边界：只做信息整理与传达，不判读病情、不输出诊疗建议；涉医疗问题一律引导就医。

### FR-08 陪诊服务（家庭端侧）

| 编号 | 功能点 | 说明 |
| --- | --- | --- |
| FR-08-1 | 发布陪诊需求 | 表单：就诊医院、期望日期、需要的帮助（参考"预约全程陪诊"演示稿）；可发布到社区需求区，或直接向商城陪诊师发起预约 |
| FR-08-2 | 知情授权勾选 | 提交前必须勾选：仅向陪诊师分享本次医院、时间和服务需求，不分享完整病历（默认不勾） |
| FR-08-3 | 服务进度同步 | 陪诊师每完成一个清单动作，家庭端实时显示；完成后回传：挂号凭证、检查陪同记录、报告获取情况、下次预约信息，自动归档到该成员就诊记录 |
| FR-08-4 | 硬件接入入口 | 预留"设备管理"入口：绑定华为/小米等智能手表（厂商开放平台），同步睡眠、运动、心率、血氧、跌倒检测；极客松阶段用模拟数据源 |

### FR-10 医疗隐私隔离（红线）

- 陪诊师端**无法调取**用户健康档案、病史、用药、报告等任何医疗资料。
- 陪诊师仅通过**分享码**获取本次任务信息：医院、时间、服务需求、诊前自我描述（如家庭授权）。
- 分享码短时效、可撤销、访问留痕；陪诊师履约中产生的照片仅含票据/凭证，不得拍摄患者正面照（后台审核）。

### FR-11 陪诊师个人经营

- 个人简介、服务范围、资质上传（平台审核后展示）；
- 档期管理：发布可约时间并上架商城；
- 收入与订单记录（极客松阶段不做真实支付，用模拟金额）。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 适老化 | 老人账号默认大字号（正文 ≥18pt）、高对比、单屏一个主任务、全部主流程 ≤3 步；文案口语化 |
| 性能 | 预警类事件端到端通知 ≤30s（关注级及以上）；陪诊动作同步 ≤5s |
| 安全合规 | 健康数据加密存储；家庭内授权可见；陪诊师最小可见；分享码短时效可撤销；符合《个人信息保护法》；不判读病情（医疗合规红线） |
| 留痕 | 全部关键操作可追溯（谁·何时·做了什么），日志不可删除 |
| 演示环境 | 极客松演示版：家庭端 Web + 本机浏览器存储（localStorage），陪诊师端/商城可用模拟数据；预留云端方案（见架构文档） |

## 9. 协作与任务分配

- **共享仓库**：`fanyuxilin-ai/kangban-family-care`（GitHub，公开仓库、仅三人协作）为本期唯一开发主线；成员私人仓库仅作原有代码备份，不再提交。
- **分支与合并**：`main` 保持可演示；所有改动在 `feat/<模块>-<功能>` 分支开发，完成后提 Pull Request，由维护者 review 后合并；文档改动放 `docs/` 目录单独提交（规范详见架构文档 §9.2）。
- **页面分区约束**：家庭端页面按设计文档 §3.1 的五 Tab 分区开发，任何成员不得把新功能堆进首页，新功能先找对应分区再动手。

- **模块化开发**：各成员在自己负责的模块目录/文档内创作，定期合并主干，避免互相覆盖。
