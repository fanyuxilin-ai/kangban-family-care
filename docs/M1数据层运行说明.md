# 康伴 M1 数据层运行说明

## 本地演示

1. Node.js 18 或更新版本即可运行配置生成脚本：`node scripts/generate-supabase-config.mjs`。
2. 在仓库根目录运行静态服务器，例如 `python3 -m http.server 8000`。
3. 打开 `http://localhost:8000`。没有有效配置时会显示“本机演示模式”，原有演示数据仍写入 `kangban-demo-v7`。

`.env` 与生成的 `supabase-config.js` 均在 `.gitignore` 中。浏览器只接收 Supabase URL 和 publishable key；不要把数据库密码、service-role/secret key 写入网页或仓库。

## Supabase 数据库迁移

迁移文件：`supabase/migrations/202611050001_kangban_cloud_core.sql`。它建立 17 张业务表、RLS、私有文件 bucket，以及报名、家庭选人、双方确认三个事务 RPC。

当前环境可通过 `npx supabase@latest` 调用 Supabase CLI，但当前 CLI 尚未登录（缺少 Supabase access token），也没有项目数据库密码，因此本轮只生成并静态检查迁移文件，没有向远端数据库执行。你可以在本机终端完成登录和链接；access token 与数据库密码只输入本机终端，不要发到聊天或提交进仓库：

```sh
npx supabase@latest login
npx supabase@latest link --project-ref sytwoulwwzfuslrgorvw
npx supabase@latest db push
```

不要将数据库密码或 Supabase access token 发到聊天或提交进仓库。云端表创建后，可用 `profiles` 只读请求确认 schema 已部署。
