# 康伴 · 家庭就医助手

**项目简介：**帮助家庭把分散的就医资料整理成一张由患者确认、可按需授权的就医信息卡，让重要信息在就诊时更容易交接。

康伴是一个手机优先的家庭就医协同原型，包含 Supabase 云端登录、社区订单及私有附件演示。没有接入真实医院、支付或医疗服务；内置病例与公开演示订单均为虚构样例。

## 当前功能

- **家庭端五 Tab 分区：**家庭端按功能域分为「首页 / 健康档案 / 医疗资料 / 陪诊 / 我的」五个 Tab——首页只放状态与入口，健康档案承载档案概览、日常记录与健康趋势，医疗资料承载就医信息卡、就诊准备、分享码、资料库与保险报销入口，陪诊承载陪诊服务全流程，我的承载家庭成员、AI 助手与设备管理入口。
- **模拟账号与四人健康档案：**内置父母 + 子女四位家庭成员模拟账号，可在顶栏切换视角；健康档案 Tab 中每位成员的档案（慢病/过敏/用药/手术史）均可展开折叠、编辑保存。
- **体检看板与异常指标跟踪：**每位成员可查看体检看板——统计卡（最近体重/体重变化/记录次数/异常待随访）、多指标趋势图、化验报告区（按天/按检查类别/全部/只看异常筛选，日期分组可折叠）与历史时间线（可编辑/删除）；支持"导入体检单"模拟 OCR 识别一份 17 项 / 6 个检查类别的完整报告（血常规、血脂四项、肝肾功能等），核对入库后异常指标自动进入跟踪并生成一般预警；**报告上基础表之外的新指标会连同参考范围自动登记进系统**（指标体系随报告扩展，无需改代码）。
- **家庭就医准备：**管理就诊清单，并记录诊前自我描述，包括症状变化、饮食、睡眠、排便和活动等情况；支持文字、照片和语音相关入口。
- **资料采集与归档：**添加检查资料和用药信息；图片可在本机通过 Tesseract.js 进行中英文文字识别，识别结果可人工编辑核对后保存。
- **服药提醒：**从识别文字生成药名、剂量、频次和医嘱明确写出的时间草稿；由家人逐项核对后保存计划并记录已服。医嘱未写清的内容不会由系统推断。
- **家庭档案与就医信息卡：**汇总家庭成员信息、检查资料和用药信息，便于就诊前整理和查看。
- **信息授权演示：**展示分享范围、短时二维码样式、访问记录和撤销入口。
- **陪诊流程演示：**家庭端可查看陪诊员介绍、预约、查看进度、互评和再次预约；陪诊员端可编辑介绍、接受预约、标记完成并互评。
- **健康预警（规则版）：**录入或模拟手表同步血压读数后，按固定规则生成红色（紧急）/ 黄色（关注）/ 蓝色（一般）三级预警；按级别完成分级告知（红色电话外呼与强提醒、黄色 App 推送、蓝色进入每日汇总），全过程在预警中心留痕。漏服提醒超时也会触发黄色预警。读数录入支持四种方式：手动填写、语音录入（模拟语音转文字）、拍照识别（模拟 OCR，需人工确认）、硬件同步（手表读数与跌倒事件演示）。
- **陪诊履约清单与佐证：**陪诊员接单后按标准化项目清单（需求文档 4.1 八项模板：电话确认、取号挂号、候诊陪同、代述病情、检查缴费取药、领取报告、复诊预约、服务小结）逐项执行；必传佐证项须上传现场照片才能完成，全部完成后才能标记服务完成；家庭端可实时查看履约进度与佐证。
- **社区需求区与接单大厅：**家庭端可发布陪诊需求帖（医院/日期/服务项/预算/需求描述，不含任何健康档案信息），陪诊师端「需求大厅」实时可见并接单；需求帖状态流转：招募中 → 已接单 → 服务中 → 已完成 / 已取消，接单后自动转入标准陪诊订单流程。
- **本次任务分享码（医疗隐私隔离）：**家庭端可为已确认/服务中的预约生成 6 位短时分享码（10 分钟有效、可撤销、访问留痕），可选是否附上诊前自我描述；陪诊员端输入分享码后仅可查看本次任务信息，陪诊师端不提供任何健康档案、病史、用药或报告的查看入口。
- **陪诊师个人经营（模拟）：**订单展示模拟报酬，工作台与个人资料页汇总累计收入、完成订单数与家庭评分；服务单提交后若填写下次复诊日期，自动为对应成员创建家庭端复诊提醒。

## 技术与数据说明

康伴为静态网页应用，可作为 PWA 添加到手机主屏幕。未配置 Supabase 时，现有家庭与陪诊师演示仍保存在当前浏览器。配置后支持 Supabase Auth、家庭云端工作区、社区报名/订单工作流和私有附件存储；云端订单基于真实账号与 RLS。陪诊师资质审核仍由项目管理员在 Supabase 管理端完成。

OCR 在本机浏览器运行。首次使用时需要加载并缓存识别组件，之后可离线识别。清晰印刷体通常更适合自动识别；医生手写中文无法保证准确，识别结果必须人工核对。可信度较低时不会自动填充资料字段或开放用药提醒生成。PDF 目前作为附件保存，字段需手动录入。

语音功能取决于浏览器支持、安全上下文和麦克风权限。浏览器关闭或设备离线时，当前版本不能保证后台定时推送。

第三方组件许可见 `THIRD_PARTY_NOTICES.md`。

## 本地运行

双击 **启动康伴.command** 可启动本机演示，并在终端显示同一 Wi‑Fi 下手机可访问的地址。也可以在项目目录运行：

```bash
python3 -m http.server 4173
```

然后在浏览器打开 `http://localhost:4173`。手机和电脑连接同一 Wi‑Fi 后，可在手机浏览器打开电脑的局域网地址；也可以将页面添加到主屏幕。

## 建议演示流程

打开家庭首页 → 勾选就诊准备项 → 添加虚构资料并确认识别内容 → 查看就医信息卡 → 浏览分享授权界面 → 在「陪诊 · 需求大厅」发布需求帖或直接预约陪诊 → 在预约卡上生成本次任务分享码 → 切换陪诊员角色，在需求大厅接单 → 工作台输入分享码查看任务信息（含授权的诊前自我描述）→ 按履约清单逐项执行并上传佐证 → 提交服务单（填写下次复诊日期）→ 返回家庭端查看履约进度、陪诊反馈与自动生成的复诊提醒 → 评价并再次预约。

可在“整理资料”中选择虚构报告或虚构处方快速体验。演示资料均为虚构内容。

## 隐私与责任边界

- 本原型不用于真实医疗服务，不提供诊断、治疗或用药建议。
- 请勿用真实患者姓名、报告、处方、保单、联系方式或其他个人身份信息进行演示。
- OCR 结果须人工核对；药名、剂量、频次和提醒时间应由患者或家属根据医嘱确认。
- 二维码、访问记录、预约和互评均为界面演示，不代表真实安全授权或服务资质核验。

## 登录、社区与 Supabase 云端

### 本机演示模式

1. Node.js 18+；仓库根目录运行 `node scripts/generate-supabase-config.mjs`。
2. 运行 `python3 -m http.server 4173`，打开 `http://localhost:4173`。
3. 登录页可选择游客、家庭演示或陪诊师演示。本机演示入口映射 `family-demo@kangban.local` / `escort-demo@kangban.local`，只保存在当前浏览器。云端演示账号使用 `kangban-family-demo@example.com` 和 `kangban-escort-demo@example.com`，可通过管理员初始化脚本重设同一演示口令；陪诊师账号由脚本设为已审核。游客只能看脱敏虚构社区帖。



云端账号初始化（只在可信本机执行）：先从 Supabase 后台取得 **service-role secret key**，不要写进仓库、网页或聊天记录；分别在当前终端设置 `SUPABASE_URL`、`KANGBAN_SUPABASE_SERVICE_ROLE_KEY`、`KANGBAN_DEMO_PASSWORD`（至少 12 位），再运行 `node scripts/provision-demo-accounts.mjs`。脚本可重复运行，账号邮箱为 `kangban-family-demo@example.com` 与 `kangban-escort-demo@example.com`；`example.com` 不接收邮件，仅供云端登录演示。

### Supabase 配置与迁移

1. 在 Supabase 建立项目，配置 Auth 邮箱登录及本地/部署站点的 Redirect URLs。
2. 将 `.env.example` 复制为 `.env`，只填写 Project URL 和 publishable key。运行 `node scripts/generate-supabase-config.mjs` 生成本地忽略文件。浏览器包不读取数据库密码、access token、service-role key 或 secret key。
3. 当前统一使用 Supabase 项目 `kangban-demo`（Project ref：`sytwoulwwzfuslrgorvw`）。安装/登录 Supabase CLI 后，对该项目执行：

```sh
npx supabase@latest login
npx supabase@latest link --project-ref sytwoulwwzfuslrgorvw
npx supabase@latest db push
```

本机 `.env` 与 Supabase CLI 链接均指向上述项目。当前六份迁移已部署并与远端迁移历史对齐；不要对旧项目 `vlxdgdrjbomdarrkrctc` 执行后续配置。迁移记录与待完成人工步骤见 [`docs/M1数据层运行说明.md`](docs/M1数据层运行说明.md)。云端演示账号可用下方脚本重复初始化。

4. 运行 `python3 -m http.server 4173` 并打开 `http://localhost:4173`。家庭/陪诊师入口支持邮箱密码注册登录；陪诊师注册初始为待审核，审核前不能报名或发布可约时段。
5. 配置可信管理员：在 Supabase Auth 找到受信任账号的用户 ID，在 SQL Editor 由项目所有者执行以下语句。该声明保存在 Auth `app_metadata`，普通用户不能自行修改；管理员需退出并重新登录以刷新 JWT。

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"kangban_admin": true}'::jsonb
where id = '<trusted-auth-user-uuid>';
```

已配置管理员登录后，「社区」下方会出现陪诊师审核队列；审核由受 JWT `app_metadata.kangban_admin` 保护的 RPC 执行。普通用户资料更新权限不包括角色或审核状态。

### 数据导入与社区边界

- 登录家庭账号后进入「社区」，点「导入本机演示数据」先查看类别/数量；确认后导入成员和云端工作区快照，将 IndexedDB 附件上传到私有 bucket，并用 `migration_runs` 保存进度和重试游标。
- 云端社区公开卡片只放医院、日期、服务类型和通用摘要；患者称呼、成员 ID 和详细需求放在 `community_post_details`，仅家庭成员可以直接读取；陪诊师需为已审核账号、是订单指定服务者，并通过十分钟有效分享码 RPC 后才可读取任务详情。
- 家庭在「社区」发布需求；陪诊师在同一社区报名并发布可约时段；家庭选人后生成订单，再由双方确认。订单区提供开始服务、Pink 的八项标准履约清单与必传佐证、完成/取消状态；任务分享码在云端以 SHA-256 摘要保存，原码仅在生成时显示，访问记录保存在订单中。已完成云端订单支持双方互评。`Companion → 需求大厅` 保留原本机演示；登录云端后该入口引导到共用云端社区，避免本地数据与云端订单混在一起。
- 云端家庭页面的数据写入该家庭受 RLS 保护的工作区快照；社区、成员索引、订单和迁移记录另有关系表。访客数据不写入云端。

- **M1 数据层：**17 表、RLS、私有 bucket 与事务 RPC 已部署到当前统一项目 `kangban-demo`（`sytwoulwwzfuslrgorvw`）；六份本地迁移文件已按远端版本对齐。

- **Pink 能力对照：**需求大厅—保留本机实现并接入云端社区；履约清单—保留八项模板并用 RPC/佐证；任务分享码—本机实现保留，云端改由订单 RPC 校验；收入—仍为模拟；互评—本机保留且云端订单新增双方私有评价。
